# RustDesk Panel 0.4 — учётные записи и адресные книги

В этой версии в существующую веб-панель добавлены **локальные учётные записи**, роли и **общие и личные книги контактов**. Это самостоятельные функции панели; они не заменяют RustDesk Server Pro и не блокируют подключения к устройствам через HBBS.

## Обновление NAS

Операции выполняются под root в SSH:

```sh
cd /volume3/docker/rustdesk-panel
wget -O /tmp/rustdesk-panel-accounts-upgrade.sh https://raw.githubusercontent.com/kostenkodm/rustdesk-panel/main/scripts/upgrade-accounts.sh
sh /tmp/rustdesk-panel-accounts-upgrade.sh
```

Скрипт скачивает `web.py`, `accounts.py`, `panel_pages.py` и `compose.yaml`, проверяет синтаксис, сохраняет исходники и каталог `state/`, **пересоздаёт только rustdesk-panel-web** и проверяет схему базы. Сервисы `HBBS` и `HBBR`, экспортёр и опрос онлайн-статусов не перезапускаются.

При неудаче скрипт восстанавливает старые исходники, старый Compose и прежнее состояние базы, потому что новые изменения в таблице сессий не совместимы с записью сессий старой версии. Папка неудачного состояния сохраняется внутри резервной копии для диагностики.

## Первый вход

После обновления откройте `http://192.168.30.150:8765` из LAN/VPN.

- Логин: `admin`
- Пароль: **тот же**, что использовался для входа в старую версию панели.

Из-за изменения структуры сессий потребуется войти повторно. Заново создавать администратора не нужно.

## Пользователи

Откройте `Пользователи` в верхнем меню. Администратор может добавить пользователя, сменить роль, отключить его, установить новый пароль (14 и более символов). Пользователь в отключённом состоянии больше не может войти, его сеансы удаляются.

Роли:

| Роль | Что разрешено в панели |
|---|---|
| `admin` | Создаёт пользователей, управляет ролями и паролями; создаёт общие/личные книги; редактирует контакты и каталог |
| `editor` | Редактирует каталог; создаёт личные книги; редактирует доступные общие и собственные личные книги |
| `viewer` | Видит каталог, общие книги и собственные личные книги, скачивает экспорт, но не меняет данные |

Личные книги доступны только владельцу. Общие книги видят все действующие пользователи панели. Изменение ролей или пароля обнуляет текущие сеансы пользователя. Последнего активного администратора нельзя отключить.

## Адресные книги

Откройте `Адресные книги`. Имеется предсозданная `Общая адресная книга`.

- Добавление контакта по RustDesk ID с названием, метками и заметкой.
- Кнопка `Добавить отсутствующие устройства из HBBS` переносит зарегистрированные IDs в выбранную книгу, не заменяя ранее сохранённые записи.
- Удаление контакта удаляет **только запись в книге панели**, не удаляет устройство из HBBS.
- Можно скачать отдельную книгу в CSV и JSON после авторизации в панели.
- Старые *явно сохранённые* карточки из `devices` переносятся в общую книгу однократно, без удаления старого каталога.

Пароли удалённого доступа не храним в адресной книге.

## Важно: синхронизация со стандартным клиентом RustDesk

Книги и учётные записи полностью работают **в веб-панели**. Однако обычные клиенты RustDesk **пока не входят в эти аккаунты и не синхронизируют книги напрямую**. Для нативной синхронизации нужен отдельный совместимый API на порту 21114 (или HTTPS на выделенном домене) с проверенной схемой ответов клиента. На текущем этапе он **не включён**: вводить аккаунты панели в клиент RustDesk бессмысленно, пока его API не реализован и не проверен.

Не публикуйте порт 8765 за пределы доверенной LAN/VPN. Web UI использует HTTP; при доступе через внешний интернет нужен TLS и дополнительная проверка безопасности.

## Проверка

```sh
docker compose -f compose.yaml ps
docker logs --tail 20 rustdesk-panel-web
curl -sS http://192.168.30.150:8765/healthz
```

Ожидаем доступную форму входа с логином и паролем, страницу `Пользователи`, страницу `Адресные книги`. Ранее найденные 23 устройства должны остаться в каталоге.
